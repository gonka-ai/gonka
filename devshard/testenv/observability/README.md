# Observability config (manual)

Files here are **not** generated by `gencompose` — the compose fragment is
[`compose-fragment.yaml`](compose-fragment.yaml), appended to the top-level
`services:` (and `volumes:`) block. Regenerate the base stack with:

`go run ./testenv/cmd/gencompose` (from `devshard/testenv`).

**Alloy (River) — source of truth**

The live pipeline in [`alloy/config.alloy`](alloy/config.alloy) is taken from
`subnet/testenv/observability/alloy/config.alloy` on branch **`subnet-testenv`**
(cAdvisor relabel, `prometheus.exporter.self`, Loki `discovery` +
`loki.process` healthcheck line drop, `queue_config`, etc.). The devshard copy
adds `prometheus.scrape "devshardd"` for `devshardd-testenv-*:9600/metrics`.
When tuning the graph, **prefer making the same change on `subnet-testenv` first
or in lockstep** so the two testenvs do not diverge.

**Images** and tags: cAdvisor, node-exporter, VictoriaMetrics, and Alloy are
aligned with the subnet stack where possible; Loki remains on 2.9 + the checked-in
`loki/config.yaml` until devshard is moved to Loki 3.

**Dashboards**

- `grafana/dashboards/cadvisor-containers.json` and
  `node-exporter-full.json` are the usual **imported** Grafana.com exports;
  commit SHAs in git history (or a PR note) if you revendor from upstream
  to make diffs reviewable.
- `grafana/dashboards/devshard-overview.json` is a **local** scaffold; wire
  panels to `devshardd_*` metrics once you rely on the Alloy scrape for
  `devshardd-testenv-*:9600`.

**Loki**

`loki/config.yaml` is mounted when the Loki service starts; it matches
`v2.9.3` single-process, filesystem-backed layout with analytics disabled.
