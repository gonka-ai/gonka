# Commitment depth growth

Implementation base: `upstream/upgrade-v0.2.17` at
`c5b9b9d373d536ead44e72b330818936b6db31ba`. This change is prepared for
review; it does not deploy or activate an upgrade.

## Commitment and recovery invariants

Each commitment is an immutable `(count, root, depth)`. Depth follows nonce
width, including sparse nonces, and cannot be estimated from successful count.
The shared regular/challenge admission builder allows nondecreasing depth up to
32 while retaining increasing counts, block/model/stage/permission/window/fee
checks and atomic batch validation. Exact-depth proof verification is unchanged.
No new chain protobuf field or historical state rewrite is needed.

DAPI workers use `GetFlushedSnapshot`, which holds one read lock and copies the
root. The getter performs no hashing, replay or I/O. The existing per-count root
index now includes depth; the existing root JSONL record persists it using the
same append and sync. Publication follows artifact/suffix persistence and the
root record. Failed publication leaves the previous published tuple available;
`Flush` can retry publication without receiving more artifacts. Partial writes
are rolled back, and recovery removes a torn trailing record before appending.

Normal replay recovers legacy depths at the existing flush boundaries. Paged
recovery checks journal/retained snapshots and incrementally reconstructs missing
boundaries. Each reconstructed root and any known stored depth must agree;
mismatches are explicit recovery errors. Legacy depth is appended to the same
root journal once. The paged recovered tip publishes its reconstructed depth.
Historical proofs still rebuild from the original starting depth and prefix.

## Early checkpoints and readiness

SQLite migrates idempotently to nullable `early_tree_depth`. NULL means legacy
unknown; a present zero or value above 32 is invalid. Fresh height-pinned captures
save the chain commitment's depth. Fingerprints include depth and checkpoint
height. Early proof requests use early depth; final by-nonce requests use final
depth. Neither value is taken from a returned proof.

A completed legacy capture marker does not imply depth completeness.
`PrepareDepths`, called before proof workers, groups unknown rows by their original
checkpoint height, queries that pinned historical stage, and checks participant,
model, count and root before filling depth. It allows at most four height queries
per invocation, a five-second total budget per preparation attempt, and three attempts per
stage/height. Preparation does not wait for a concurrent capture; complete stages
are cached until pruning, and failed attempts are cached until pruning. Invalid known values are not silently
replaced. `MaybeCapture` also repairs legacy completed captures without recapturing
at the latest height.

A completely missed capture keeps the existing stage-level guard skip behavior.
An unreadable capture, or a present captured row with unknown/invalid depth,
causes local abstention, including in observe mode. It does not clear the
participant's miss streak or generate a fraud vote. Invalid proof responses
remain hard failures. An absent participant row in a completed capture still
receives ordinary zero-early-share accounting.

**Activation prerequisite:** deploy the DAPI repair before the consensus change.
Require fresh complete depth-bearing captures for every regular/confirmation
stage still awaiting validation, or verified successful historical preparation.
Check adoption and actual positive-vote availability across assigned validators
and guardians. A local readiness error or inadequate votes must defer the
scheduled chain activation; abstention is only a temporary local failure mode.
All chain nodes must switch admission rules at the same coordinated upgrade
height. This repository change cannot establish fleet readiness by itself.

## Regression evidence

The affected DAPI artifact, earlyshare, worker, and public proof endpoint packages
pass. Keeper and module regressions cover regular/challenge admission, two-model
atomic batches, equal depth, 24→25→31→32 growth, decreases, invalid bounds and
nonincreasing count. The chain fixtures are generated by the real artifact store
and checked against that implementation by `TestSMSTAdmissionFixtures`.

Store regressions cover sparse nonce widths, old proofs after expansion, forced
cold reconstruction, spill/reopen, legacy records, torn tails, short writes,
fsync failures, same-count retry and concurrent worker snapshot construction.
The pinned-depth subtree-reuse and nonce/dense-index uniqueness tests remain
unchanged. Race-detector checks cover the affected store and worker paths.

Early guard regressions use real stored proofs and the production proof-item
verifier: early-24/final-25 passes, while changed/removed artifacts and either
wrong depth fail. Migration preserves legacy rows and completed markers.
Backfill provenance, retry/query bounds, unknown-depth abstention, miss-streak
preservation and fingerprint changes are tested.

Challenge scoring uses real commit and vote handlers plus the real segment
evaluator for two models and rotation. Accepted expanded work remains ACTIVE
without exclusions or collateral debit. A retained-early-count control fails,
becomes INACTIVE and incurs exactly one debit. The collateral fixture is funded
and stateful; it is not a live bank or full-chain/GPU integration. Vote-readiness
coverage demonstrates that enough actual positive votes or a prepared guardian
are needed; widespread legacy abstention can reject work.

Temporarily restoring the old equality guard makes both real-handler and expanded
challenge tests fail at 24→25 admission. The fixed source is restored afterward.
Fixtures use small counts and sparse jumps to test deterministic boundaries;
they do not demonstrate GPU throughput or full-duration challenge reachability.

## Cost measurements

Local Apple M5, darwin/arm64, Go 1.25.9; short microbenchmarks, not production
capacity measurements. Filesystem synchronization dominates these small recovery
fixtures, so the figures do not establish asymptotic performance by themselves.

| Measurement | Result |
| --- | --- |
| Atomic flushed tuple | 15.53 ns/op, 32 B, 1 allocation |
| Proof verification, depth 24 | 2.206 µs/op, 1696 B, 26 allocations |
| Proof verification, depth 32 | 2.452 µs/op, 2208 B, 34 allocations |
| Legacy paged recovery, 16 / 64 boundaries | 125 / 308 ms |
| Legacy RAM recovery, 16 / 64 boundaries | 107 / 287 ms |

Depth 32 adds eight 36-byte proof elements (288 raw bytes) versus depth 24.
Fault-injection tests count root-record syncs and confirm retry uses the existing
journal sync; the normal flush adds no separate depth journal or extra fsync.
Historical depth recovery uses the existing replay/journal and incremental upper
trees, rather than rebuilding each artifact prefix independently.

## Follow-up review (2026-11-02)

The review found and fixed these implementation issues before committing:

| Priority | Issue found | Correction |
| --- | --- | --- |
| P1 | A completely missed early capture caused stage-wide abstention, changing existing vote availability. | Preserve the existing guard skip when no completed capture exists. Present legacy rows with unknown depth remain a separate local preparation error. |
| P1 | Pre-validation backfill waited on the global capture lock and could spend four consecutive RPC timeouts before launching proof workers. | Use nonblocking lock acquisition and one five-second budget for the whole preparation attempt. Respect caller cancellation. |
| P2 | Already-complete stages reread all checkpoints twice on every capture tick. | Cache completed preparation until stage pruning and avoid an unnecessary second read when no backfill query ran. |
| P2 | Persisted zero depth was treated as absent legacy metadata; negative/overflow/string depths could be skipped as malformed records. | Use nullable persisted depth and reject explicitly invalid depth metadata. Legacy absent depth still reconstructs and backfills normally. |

The missed-capture, lock-wait and repeated-read regressions were reproduced by
new tests before repair. Added tests also cover cancellation, cache invalidation,
invalid persisted depth, one-time backfill, and a crash after an expansion/spill
whose root publication failed. All added Go comments were removed as requested;
unchanged original comments remain.

Broader review checks include the full `inference-chain/x/inference/...` suite,
compilation of every DAPI package/test, and full affected-package race runs.
Operational readiness and a coordinated testnet run remain release prerequisites;
these local checks cannot certify a live mixed-validator rollout.
